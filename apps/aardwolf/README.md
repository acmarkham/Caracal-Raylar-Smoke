# Aardwolf firmware

This app implements the [Aardwolf ADR](../../SpecAndDesign/ADR/apps/app/_aardwolf/ADR%20Aardwolf%20GPS-Calibrated%20Audio%20Logger.md) for Raylar v1.0. It starts in energy recovery, powers GPS and the microphone only after reported battery SOC exceeds 20%, and pauses audio, GPS, and radio when SOC falls below 10%. Heartbeats resume at the next complete UTC half-hour epoch after recovery.

GPS green follows the shared UI policy: solid while the powered receiver is searching or reacquiring, a 50 ms pulse for each new GPS PPS anchor accepted by the Time Service while tracking, and off in standby, power transitions, receiver error, or off. Receiver state is checked every 50 ms independently of buzzer playback, so the search indication does not wait for PPS or a time publication.

Build with `cargo build -p aardwolf --release --target thumbv8m.main-none-eabihf`. The binary is `target/thumbv8m.main-none-eabihf/release/aardwolf`. No automatic flashing is part of the build.

`bench-external-power` bypasses the boot SOC gate for externally powered bench work, while still applying the below-10% pause once a valid SOC is reported. It must stay disabled for the solar run. `bench-rx-beep` enables a short audible indication for each valid heartbeat received; field builds leave it disabled.

The fixed run configuration is in `config.rs`: 868.1 MHz and 2441 MHz, twelve ordered profiles, a 30-minute UTC epoch, and 16-byte V4 heartbeats. Nodes must run the same network and schedule version. Slot permutation is based on NodeId, epoch and profile minute. Minutes 4 and 12 use two-second slots. The radio sleeps for minutes 13–30 and throughout energy recovery.

Audio uses the mono 16 kHz reference microphone configuration and creates one 32-bit FLAC per UTC minute in hourly folders, using 2048-sample blocks. Partial final frames preserve the actual sample count. The encoder is heapless and selects fixed predictors of orders 0–4 and Rice parameters by encoded size, with constant and verbatim fallbacks. FLAC files use frame CRCs; the optional STREAMINFO MD5 is deliberately absent. A file is opened exclusively after its first PCM arrives, so an empty segment creates no file and a repeated timestamp cannot append to or overwrite an earlier recording. Audio starts only when the card has room for a worst-case uncompressed FLAC minute, metadata and frame overhead, plus the 100 MB log reserve. System and radio events are written to the normal system log when the card is available; a missing card leaves the radio and heartbeat task running with storage error bits set.

WAV remains the repository's default recording format and the Audio Recorder Service's `new` constructor. Aardwolf explicitly uses `new_flac_with_buffers` with const-initialized static workspace. The [FLAC service ADR](../../SpecAndDesign/ADR/services/audio/Service%20FLAC%20Encoder.md) records the codec and lifecycle design. Independent decoder checks and the SD fixture test are documented under [servicetests/flacencoder](../../servicetests/flacencoder/README.md); sustained capture with concurrent radio/logging still needs hardware validation.

Every ten seconds, `audio timing` records maximum codec and append time plus peak source backlog. In mono mode, the frame budget is 128,000 microseconds and retention is 128,000 samples (eight seconds). Codec timing includes executor yields; append timing includes the shared storage lock wait. A growing backlog means recording is not keeping pace even while individual FLAC frames remain valid.

Hexaphonic recording is enabled by default for current testing: acquire MIC1..MIC6 and record a `.CRCL` companion beside each mono FLAC minute. To build mono explicitly, use `--no-default-features --features firmware,core-smps`. MIC1 retains the existing signed 32-bit reference PCM; the other channels use in-place spatial differences, 1024-frame blocks, 10-bit quantization and direct Rice with packed quantized fallback. `config.rs` exposes the block length and precision. The service API also supports temporal/automatic Rice and a WAV reference. See the [multichannel ADR](../../SpecAndDesign/ADR/services/audio/Service%20Multichannel%20Audio%20Recording.md) and [target checks](../../servicetests/crclencoder/README.md).

Hexaphonic recording uses one source reader and one paired lifecycle. Both files share the UTC filename stem, segment identity, sample interval and final sample count. Storage admits the entire pair plus the protected log reserve before opening either member; three stream slots permit the reference, companion and system log together. Pair errors stop recording and preserve existing files. The 127,998-scalar-sample hexaphonic ring retains about 1.33 seconds at 16 kHz; the mono ring retains eight seconds. `audio timing` reports combined codec time and paired writes, with a 64,000-microsecond CRCL block budget in hexaphonic mode.

Build with `--features cheap-crcl` to select experimental CRCL v2: independent per-channel shift quantization, temporal-only prediction, estimated Rice k, and no CRCL CRC or reference PCM SHA-256. MIC1 remains lossless FLAC and the paired lifecycle remains aligned; standard FLAC frame CRCs remain. The v1 spatial algorithm remains the normal hexaphonic default. See the [variant definition](../../crates/services/crclencoder/cheap.md) and [bench results](../../servicetests/crclencoder/cheap-profiling.md).

Use `scripts/crcl_decode.py` with the matching reference to verify and reconstruct six-channel WAV. It detects v1/v2 automatically and reports the absence of integrity checks for v2. Quantization precision is an evaluation setting pending beamforming and angle-of-arrival quality measurements; the successful laboratory board test does not establish acoustic calibration or GPS timing accuracy.

Every 60 seconds, `/syslog.txt` records three-axis acceleration in milli-g, three-axis magnetic field in nanotesla, and the LIS2HH12 and LIS2MDL die temperatures in milli-Celsius under `Sensor`. The `Cpu` component records average executor CPU load over the preceding 60-second window, with active, idle and elapsed milliseconds. These diagnostics also run during energy recovery. CPU idle measurement follows Integration 002 and includes interrupt work before the executor wakes. Sensor startup failures are retried each minute, and read failures are logged without stopping the app.

The firmware uses a deliberately empty global allocator. The normal exFAT mount, file lookup, create, append and flush paths use bounded storage. Any unexpected allocation fails, which makes heap use visible during bring-up. This and the seven-day data-integrity target require hardware verification.

Before a week-long campaign, verify RF packet-complete margins, GPS holdover timing, SD throughput, audio continuity while radio RX is active, the two SOC thresholds, and the card-full and card-absent cases on physical boards. Configure the antenna and regional EIRP/duty-cycle policy for the deployment; the checked-in firmware logs the antenna as `unknown` until that detail is supplied.
